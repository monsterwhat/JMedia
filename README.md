# JMedia

JMedia is a self-hosted media server for a local music library, a local video
library, and IPTV sources exposed over the Xtream Codes API. It is a Quarkus
(Java) application with a browser UI for desktop and mobile. Media files stay on
the host and are streamed by the server.

Version: derived from com.playdeca.JMedia/pom.xml (see that file for the current release).

Playback of local media is served by this host and does not require a cloud
account. Optional metadata lookups, IPTV providers, update checks, and AI
subtitle generation do contact external services; see
[Privacy and data flow](#privacy-and-data-flow).

## Requirements

- JDK 25 or newer. The build sets `maven.compiler.release` to 25, and CI uses
  Temurin 25.
- Maven 3.9 or newer to build from source.
- FFmpeg and FFprobe on `PATH` for probing, transcoding, HLS, and embedded
  subtitle extraction. Features that need them report the missing binary rather
  than stopping the server.
- A writable home directory. H2 databases are stored as files in `~/.jmedia/`
  (`jmedia-settings`, `jmedia-music`, `jmedia-video`), and the log is written to
  `~/.jmedia/jmedia.log`.
- Optional: Python 3 with Transformers/PyTorch for AI subtitles, Tesseract for PGS
  subtitle OCR, and yt-dlp/spotDL (with Node.js or Deno) for URL imports.

## Quick start

Build the runnable uber-jar from the Maven module:

```bash
cd JMedia/com.playdeca.JMedia
mvn -o package
java -jar target/JMedia-runner.jar
```

`-o` runs Maven offline and assumes the dependencies are already in your local
repository. Omit it on a first build so Maven can download them. Quarkus writes
the artifact as `target/JMedia-runner.jar`.

On first start:

1. Open http://localhost:8080.
2. Sign in as `admin` with the one-time password printed in the startup log. It
   is generated by `Services/AdminUserService` and logged once, to the console
   and to `~/.jmedia/jmedia.log`.
3. Set your own password. It must be at least 12 characters. Until it is changed,
   the auth filter blocks the UI and authenticated API routes, allowing only
   `/api/auth/`, `/change-password.html`, and the static assets those pages need.
4. Configure library paths and metadata providers in Settings.

The server listens on `0.0.0.0:8080` by default (`quarkus.http.port`).

## Feature status

| Status | Meaning |
| --- | --- |
| Stable | covered by automated tests |
| Experimental | implemented, known limitations |
| Planned | documented, not implemented |

| Area | Status | Notes |
| --- | --- | --- |
| Music library, playback queue, playlists | Stable | Metadata, queue persistence, and playlist CRUD. Queue advance and genre filtering have unit tests. |
| Video library and scanning | Stable | Recursive scanning, episode/season naming, thumbnails, and storyboards. Naming and season logic have unit tests. |
| Xtream live TV, VOD, series | Stable | `/player_api.php`, `/get.php`, and `/xmltv.php`. M3U parsing, catch-up, and live groups have unit tests. |
| Transcoding and HLS | Stable | FFmpeg-backed. Command construction and HLS session cleanup have unit tests. |
| DJ Mode | Experimental | Beat-aligned crossfade and scoring. Open work is tracked in the [DJ Mode plan](JMedia/com.playdeca.JMedia/docs/dj-mode-plan.md). |
| AI subtitle generation | Experimental | NVIDIA Parakeet TDT plus NLLB translation through a local Python process. Optional dependencies; no automated coverage. |
| PGS subtitle OCR | Experimental | Tesseract conversion of image-based subtitles. Requires a separate Tesseract install. |
| Cross-server sync | Experimental | Partial: songs, videos, collections, and subtitle tracks only. Playlists, playback progress, watch progress, and timelines are NOT synced. See the [sync matrix](JMedia/com.playdeca.JMedia/docs/sync-matrix.md). |
| Native image build | Planned | A `native` Maven profile and `build-native.bat` exist, but CI publishes only the uber-jar and does not build or test a native image. |

"Stable" means the main path has automated unit coverage, not that every
endpoint has an integration test. The test suite is unit tests only; there are no
`@QuarkusTest` integration tests.

## Configuration highlights

- `jmedia.local-network-cidrs` is a comma-separated list of CIDRs or exact IPs
  that receive a non-`Secure` session cookie, so LAN clients can use plain HTTP.
  The default in `application.properties` covers three private subnets plus
  loopback. Clients outside the list get a `Secure` cookie and need HTTPS, usually
  through a reverse proxy.
- The sync API key is generated in Settings, Sync (`POST
  /api/sync/settings/generate-api-key`) and stored in the local settings database.
  Incoming sync requests must send it as `X-JMedia-Sync-Key`; outbound peers are
  configured with a base URL and the peer's key. Sync is disabled by default, and
  the schedule defaults to `0 0 3 * * ?` (`sync.schedule`).
- Metadata API keys and provider toggles are stored in the settings database and
  edited in the UI. Disabling a provider makes the features that depend on it
  degrade instead of failing.

## Privacy and data flow

Media files are never uploaded. Scanning, playback, transcoding, HLS, and audio
analysis run on the host. The application properties configure no telemetry or
analytics endpoint.

Optional features send lookups to these services:

| Service | Data sent | Used for |
| --- | --- | --- |
| TMDb (`api.themoviedb.org`, `image.tmdb.org`) | Title or TMDb ID | Film/TV metadata and artwork |
| OMDb (`omdbapi.com`) | IMDb ID or title | Ratings and extra details |
| MusicBrainz (`musicbrainz.org`) | Artist/title search or MusicBrainz ID | Music metadata |
| Deezer (`api.deezer.com`) | Artist/title search | Album art and genres |
| TheAudioDB (`theaudiodb.com`) | Artist/title search | Backup album art |
| AcousticBrainz (`acousticbrainz.org`) | MusicBrainz recording ID | BPM and key data |
| IMDbAPI (`api.imdbapi.dev`) | IMDb ID or title | Series ID lookup |
| TVMaze (`api.tvmaze.com`) | Show title or ID | Show and poster fallback |
| IntroDB (`api.introdb.app`, `api.theintrodb.org`) | IMDb ID, season, episode | Intro/outro timestamps |
| GitHub (`api.github.com`) | Repository/release lookup | Update check |
| Hugging Face (via Transformers) | Model download request | Parakeet/NLLB weights on first AI subtitle run |
| unpkg.com | Browser request for a stylesheet | PrimeIcons on the login page |
| Your IPTV/EPG provider | The URLs and credentials you configure | Live streams, VOD, series, and guide data |

Provider lookups send titles, artist names, or public IDs; audio and video
content is not uploaded. AI subtitle generation runs locally and does not upload
media, though the first run may download model weights.

Cross-server sync sends metadata JSON to the peers you configure (songs, videos,
collections, and subtitle tracks). It does not send playlists, playback position,
watch progress, timelines, user accounts, or the media files themselves.

URL imports pass the URL to yt-dlp or spotDL, which contact the source service.

## Development

```bash
cd JMedia/com.playdeca.JMedia
mvn -o test
```

From the repository root, check documentation consistency:

```bash
bash scripts/check-docs.sh
```

The script fails when required docs are missing, when README references a local
path that does not exist, when a release version is hardcoded in the README, when
the published jar name drifts from the workflows, or when banned claims appear.
The same script runs in the `Build` workflow before the Maven package step.

DJ Mode has its own browser gate. It needs a running instance and Playwright
(`cd JMedia/scripts && npm install && npx playwright install chromium`):

```bash
node JMedia/scripts/dj-fade-check.mjs --base http://127.0.0.1:8080 --password '...'
node JMedia/scripts/dj-fade-check.mjs --base http://127.0.0.1:8080 --password '...' --mode drift
```

It asserts that the fade lasts the planned duration within 250 ms, that both
gains cross monotonically and overlap for at least 80% of the plan, and that a
planned entry beyond 45 s clamps to 45 s. `--mode drift` stalls the audio element
for 14 s so the server clock runs ahead, then verifies the planned mix still
executes; that is the failure mode that used to turn a beat-aligned transition
into a manual fade.

The packaged-runtime integration tests live in `JMedia/scripts/it/` and run as the
`Integration (packaged runtime)` CI job. Each one starts the uber-jar against a
throwaway home directory on port 8099 and exercises one boundary:

| Script | Covers |
| --- | --- |
| `it/it-bootstrap.sh` | Fresh install, generated password, forced change, restart persistence |
| `it/it-migration.sh` | Opens a 1.46.4 database with the current jar; schema upgrade and legacy admin healing |
| `it/it-sync.sh` | Sync key matrix: no key, guessed key, session-only, valid key, restart persistence |
| `it/it-hls.sh` | Real ffmpeg: scan a clip, create an HLS session, serve segments, destroy the session |

Run one locally with `JAR=path/to/JMedia-runner.jar bash JMedia/scripts/it/it-sync.sh`
(needs JDK 25; set `JAVA_BIN` if `java` is not on PATH for the right version).

See `API.md` for the HTTP API and `JAVA_REQUIRED.md` for JDK installation notes.
